# Constructor Studio Theorem Kit

A [Constructor Studio](https://github.com/constructorfabric/studio) kit for **machine-checkable mathematical claims**: verifying published proofs as claim graphs, certifying finite statements with exact witnesses, and finding, stating and proving new statements with Lean 4 as the judge. The kit is domain-neutral; quantum information theory ships as the first example pack (`examples/qi/`), number theory as the second (`examples/euler-polynomial/`).

The kit packages an artifact pipeline for two kinds of claim. *Finite ones* — "no model of class X reproduces object Y", "this instance is infeasible", "this candidate is a counterexample" — where the proof is an **exact certificate** (a Farkas vector, an SOS decomposition, a DRAT proof, an exhaustive enumeration) found by heavy computation but checkable cheaply and deterministically. And *general ones* — conjectures and published theorems — where the proof is a **Lean 4 development** checked by the compiler rather than by the agent that wrote it.

```
find (SDP / SAT / search / LLM / human, days)  ≫  check (exact arithmetic or the Lean kernel, seconds)
```

Trust never lives in the search. Only the certificate and its checker need to be believed — so the kit makes certificates and check-runs first-class, traceable, gated artifacts.

## Artifact pipeline

```
RESEARCH-PLAN ──▶ CONJECTURE ──▶ PROOF-ATTEMPT   (discovery layer: new statements, Lean-attested)
                      │ tier A route / counterexample
                      ▼
CLAIM ──▶ CERTIFICATE ──▶ CHECK-RUN              (certificate layer, self-contained)
  ▲
THEOREM ──▶ PROOF-MAP ──▶ LEMMA                  (theorem layer: published proofs as claim graphs)

VERIFICATION-PLAN gates the verification workflows; RESEARCH-PLAN gates the discovery ones.
principles.md (P1–P13) binds all ten kinds; AGENTS.md is the agent's map.
```

- **CLAIM** — a precise finite statement with exact data: typically an impossibility ("no model of class X reproduces Y"), an infeasible instance, or the exact data of a confirmed counterexample.
- **CERTIFICATE** — the witness: file reference + SHA-256 + mathematical semantics + provenance. Never inlined, never trusted by origin.
- **CHECK-RUN** — a record of one verification of one certificate in one environment. **Script-generated, never hand-written.** Trust grows with environment diversity across runs.
- **THEOREM / PROOF-MAP / LEMMA** — a published proof as a claim graph with statuses `formalized / machine-checked / expert-verified / cited / open`, computed from artifacts, never asserted.
- **RESEARCH-PLAN** — one discovery run: the question verbatim, prior knowledge marked verified/assumed, a definitions concordance (informal ↔ Lean), formalization cost confirmed by a human, budget in attempts and hours, the admissible origins of conjectures, the conjecture register, and the **frozen success criteria** every attempt is judged by.
- **CONJECTURE** — one new statement: informal and *compiled* formal statement (the `#check` output of a stub), a mandatory **Faithfulness Cross-Check** (an independent reader back-translates the Lean block into prose without seeing the informal statement, compared element by element; the Lean definitions evaluated on the same instances as the exploration record), origin, exact instance evidence before any attempt, relations, attempts, and a status `open / supported / proved / refuted / withdrawn` **derived** from attempts and claims.
- **PROOF-ATTEMPT** — one attempt at one conjecture by one route. **Script-generated by `attest_lean.py`**: build, `#print axioms`, `#check` against the conjecture's formal statement, pinned dependencies — a verdict *vector*, no confidence score, sealed by a hash the gate recomputes. The agent fills only assumptions, deviations and the handoff.

The certificate layer works bare (no theorem needed). The theorem layer references down into it. The discovery layer routes finite claims through it (tier A) and refutes conjectures with it (counterexample CLAIMs) or with Lean (`--refutes`).

## Gates (four layers)

1. `constraints.toml` — structure and traceability via `cfs validate`: required sections for all ten kinds, ID grammar (`cpt-{system}-{claim|cert|run|thm|pm|lem|vplan|rplan|conj|attempt|criterion}-{slug}`), reference chains (CLAIM ← CERTIFICATE ← CHECK-RUN, CONJECTURE ← PROOF-ATTEMPT, criterion ← PROOF-ATTEMPT verdict rows).
2. `scripts/` — the computational gates: `checkers/` (one exact checker per certificate format, each *generating* CHECK-RUN artifacts under the contract in `scripts/checkers/README.md`; `fast_inflation.py` is the first), `attest_lean.py` (Lean attestation that *generates* PROOF-ATTEMPT artifacts), and `graph_gate.py` (cross-artifact semantics G1–G8: theorem status computed from load-bearing nodes, lemma status ≤ artifacts, certified claims have passing runs, conjecture status derived from attempts and claims and *refuted stays refuted*, attempt verdicts unedited since generation, plan registers consistent).
3. `workflows/` — agent orchestration with hard rules (a status may never be claimed without its artifact; no heavy work without an approved plan).
4. `principles.md` — thirteen cross-cutting invariants every `rules.md` loads first: evidence kinds never pooled, definitions reconciled before the first attempt, cost asked from a human, instances before formalization, conjectures derived not guessed, strongest-supported statements, criteria agreed and frozen, the checker is the judge, statements verified before they license a step, refuted stays refuted, trust never lives in the search, human gates in the record, and **the formal statement cross-checked against the informal one by an independent reader and on instances before any attempt** (the compiler never checks that a theorem says what you meant).

## Example packs

Examples live under `examples/<pack>/<KIND>/` and are gated per pack: `python3 scripts/graph_gate.py examples/<pack>`.

**`examples/qi/` — quantum information theory** (the kit's origin):

- **Certificate layer — EJM.** The **Elegant Joint Measurement** distribution in the triangle network (Gisin 2019, conjecture; Gitton–Renner 2025, proof — [arXiv:2510.15143](https://arxiv.org/abs/2510.15143)): non-3-locality certified by a 2×2×4-inflation Farkas certificate, reproduced independently on macOS/arm64 without the commercial LP solver.
- **Theorem layer — PGR.** Bipartite bound information exists (Pauwels–Gisin–Renner): a 7-node claim graph with honest statuses and the weakest link named.
- **Discovery layer — CHSH.** A deliberately small research run in core Lean (no Mathlib, builds in 2 s): an exact enumeration suggests the CHSH deterministic bound (CONJECTURE, **proved** by a script-attested Lean attempt), its over-generalization to all ±1 coefficient patterns is **refuted** by a Lean witness (`attest_lean.py --refutes`), and the restriction the handoff suggests is registered as **supported** by a 128-case exact check. See `examples/qi/lean-chsh/`, `examples/qi/chsh-enumerate.py`.

**`examples/euler-polynomial/` — number theory** (no physics, core Lean): Euler's polynomial n² + n + 41. The famous pattern "prime for every n" is registered from an exploration record, **refuted** in Lean at n = 40 (1681 = 41²), the restriction to n < 40 is **proved** by `decide`, and the deeper statement that no prime below 41 ever divides n² + n + 41 is registered as **supported** by exact enumeration. Same artifact kinds, same scripts, same gates — nothing in the kit knows which domain it is in.

## Usage

See [USAGE.md](USAGE.md) — standalone quickstart (no Studio needed): tour the examples, run the semantic gate, re-verify a real nonlocality certificate in 30 seconds, re-attest a Lean proof in 10.

## Install

```bash
cfs kit install omniscale-ai/studio-kit-qi
```

The slug `studio-kit-qi` is historical (the kit started as a quantum-information kit and keeps its install identity); the kit itself is domain-neutral.
