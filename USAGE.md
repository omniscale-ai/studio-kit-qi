# Using the Theorem Kit locally

No Constructor Studio installation is required for the standalone workflow — just `python3` (3.9+, stdlib only) and `git`.

## 0. Get the kit

```bash
git clone git@github.com:omniscale-ai/studio-kit-qi.git && cd studio-kit-qi
```

## 1. Tour the artifact chain (5 minutes, read-only)

Worked examples ship as packs under `examples/<pack>/<KIND>/`. The quantum-information pack `examples/qi/` has three chains; the number-theory pack `examples/euler-polynomial/` has one (see §1b).

**Certificate layer (EJM):** read in this order —

```
examples/qi/CLAIM/example-ejm.md            # the impossibility statement + exact data
examples/qi/CERTIFICATE/example-ejm.md      # the witness: file, SHA-256, checking predicate
examples/qi/CHECK-RUN/example-ejm-macos.md  # one verification in one environment (hand-assembled bootstrap record)
examples/qi/CHECK-RUN/example-srb-222-linux-py.md  # one verification by the kit's own checker (script-generated, Linux/x86_64)
examples/qi/records/checkrun-srb-222-macos-20260810.md  # the first run of that checker, macOS/arm64 — raw record, not a registered artifact
```

**Theorem layer (PGR bound information):**

```
examples/qi/THEOREM/example-pgr.md          # statement + trust summary (weakest link named)
examples/qi/PROOF-MAP/example-pgr.md        # the 7-node lemma DAG with statuses
examples/qi/LEMMA/example-pgr-*.md          # per-node statement + verification route
```

**Discovery layer (CHSH, deterministic bounds):**

```
examples/qi/RESEARCH-PLAN/example-chsh.md                   # the run: question, concordance, cost, budget, policy, register, frozen criteria
examples/qi/CONJECTURE/example-chsh-det-bound.md            # proved   — origin: pattern in exploration
examples/qi/CONJECTURE/example-bell-pm-coeff-values.md      # refuted  — origin: generalization; witness E = 4
examples/qi/CONJECTURE/example-bell-odd-sign-values.md      # supported — origin: restriction; 128-case exact check, no attempt yet
examples/qi/PROOF-ATTEMPT/example-chsh-det-bound-lean.md    # status pass    (generated by attest_lean.py)
examples/qi/PROOF-ATTEMPT/example-bell-pm-coeff-values-refute.md  # status refuted (generated by attest_lean.py --refutes)
examples/qi/chsh-enumerate.py                                         # the exploration record (exact integer enumeration)
examples/qi/lean-chsh/                                                # the Lean project: Chsh.lean (proofs), Stubs.lean (statement stubs), Instances.lean (instance agreement)
```

## 1b. The number-theory pack (no physics)

```
examples/euler-polynomial/RESEARCH-PLAN/example-euler.md                 # the run: Euler's n² + n + 41
examples/euler-polynomial/CONJECTURE/example-euler-all-prime.md           # refuted  — the famous pattern, witness n = 40 (1681 = 41²)
examples/euler-polynomial/CONJECTURE/example-euler-prime-below-40.md      # proved   — restriction of the refuted one, by decide
examples/euler-polynomial/CONJECTURE/example-euler-no-small-prime-factor.md  # supported — no prime below 41 divides f(n); exact check, no attempt
examples/euler-polynomial/PROOF-ATTEMPT/*.md                              # script-generated
examples/euler-polynomial/lean-euler/                                     # Euler.lean, Stubs.lean, Instances.lean
examples/euler-polynomial/enumerate.py                                    # the exploration record
```

Every artifact kind has `template.md` (structure), `rules.md` (hard rules, each loading `principles.md` first), `checklist.md` (review questions) under `artifacts/<KIND>/`; the examples live in the packs. `AGENTS.md` is the one-page map.

## 2. Run the semantic gate

```bash
python3 scripts/graph_gate.py examples/qi
python3 scripts/graph_gate.py examples/euler-polynomial
```

Expected: `graph_gate: 20 artifacts scanned` … `PASS` for the QI pack and `graph_gate: 6 artifacts scanned` … `PASS` for the number-theory pack. The gate enforces what static validation can't: theorem statuses are computed not asserted (G1), lemma statuses never exceed their artifacts (G2), every load-bearing node resolves (G3), `certified` claims have passing runs (G4), approved plans carry an approval (G5, G8), conjecture statuses are derived from attempts and claims and *refuted stays refuted* (G6), attempt verdicts are untouched since the script wrote them — an owned-sections SHA-256 is recomputed (G7), and plan registers agree with the conjectures (G8). Try breaking it: edit `examples/qi/THEOREM/example-pgr.md` frontmatter to `status: verified` and re-run on `examples/qi` — G1 fails with the exact offending nodes; or change `status: pass` to `status: refuted` in a PROOF-ATTEMPT example — G7 reports the hash mismatch.

## 3. Re-verify a real nonlocality certificate (30 seconds, QI pack)

Fetch the certificate data (sparse clone, ~20 MB):

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/vgitton/fast-inflation fi
git -C fi sparse-checkout set data
```

Verify integrity against the declared hash, then run the independent checker:

```bash
echo "6db0eb30dffb77b5603cde96efd9ad5ffac93ac0032946a7a94b81e527fa72d4  fi/data/srb_222_certificate.txt" | shasum -a 256 -c -
python3 scripts/checkers/fast_inflation.py fi/data/srb_222_certificate.txt \
    --repo fi --target srb --system qi --check-run my-first-checkrun.md
```

Expected output ends with:

```
min score (exact): 169346701327/80000000000
VERDICT          : VALID — min score > 0: the inflation LP is infeasible;
                   the target distribution is NOT triangle-local at this visibility.
```

You have just re-proven, on your machine, in exact arithmetic, with an implementation that shares zero code with the original, that the shared-random-bit distribution at visibility 41.422% is nonlocal in the triangle network — and `my-first-checkrun.md` is the CHECK-RUN artifact recording it. That file is the unit of trust in this kit: script-generated, hash-anchored, environment-stamped.

What the checker does is specified in `scripts/checkers/FAST-INFLATION-SEMANTICS.md` — precisely enough that you could write a third implementation from it alone. Checkers are pluggable: one script per certificate format under `scripts/checkers/`, all emitting CHECK-RUN artifacts under the contract in `scripts/checkers/README.md`.

(The EJM 2×2×4 certificate needs the symtree-based event enumerator — the marked extension point in `fast_inflation.py`; today it is checked via the ported original code, see the EJM CHECK-RUN example.)

## 3b. Re-attest a Lean proof (10 seconds)

The discovery layer's unit of trust is a PROOF-ATTEMPT written by `scripts/attest_lean.py` from the compiler's own output. Regenerate the kit's passing example (needs [elan](https://github.com/leanprover/elan); the pinned toolchain downloads on first use):

```bash
python3 scripts/attest_lean.py --project examples/qi/lean-chsh --file Chsh.lean \
    --decl Chsh.chsh_det_le_two \
    --conjecture examples/qi/CONJECTURE/example-chsh-det-bound.md \
    --slug chsh-det-bound-lean --out /tmp/attempt.md
```

Expected output ends with:

```
  pass  criterion-statement-matches                   type equals the Formal Statement
  pass  criterion-dependencies-pinned                 leanprover/lean4:v4.35.0; 0 package(s)
  pass  criterion-statement-confirmed                 kit maintainer, 2026-10-13
STATUS           : PASS — every criterion row passes; the declaration proves the conjecture's formal statement
```

Six rows, each measured, none weighted: `lake build` exit; `sorryAx` absent from `#print axioms` (the build exit code does *not* detect `sorry`); axioms within the allowed set; the declaration's `#check` type equal to the CONJECTURE's compiled Formal Statement; toolchain and packages pinned; and the one judged row — the CONJECTURE's Faithfulness Cross-Check: an independent reader (here a second agent instance shown only the Lean code and the concordance) back-translated the block into prose and it was compared with the informal statement element by element, the Lean definitions were evaluated on the same instances as the exploration record (`Instances.lean`), and a named person confirmed — copied, never filled by the attempt. Add `--refutes` and point at `Chsh.not_bell_pm_one_in_pm_two` with the refuted conjecture to see the other path. The script never writes `proved`: it writes `pass`, `refuted`, `incomplete` or `error`, and `graph_gate` derives the conjecture's status from that.

## 4. Author your own claim graph

1. Copy templates from `artifacts/*/template.md`; follow the matching `workflows/*.md` (they are agent-facing but human-readable):
   - **verifying a published result? start here** → `workflows/plan-verification.md`: interactive brainstorm (scope, depth menu with costs, allowed interventions, budget) producing a VERIFICATION-PLAN — the verification workflows gate on an approved plan
   - **finding or proving something new? start here** → `workflows/plan-research.md`: brainstorm (question, concordance, routes and cost, budget, frozen success criteria) producing a RESEARCH-PLAN — the discovery workflows gate on it
   - new impossibility result → `workflows/decompose-proof.md` (THEOREM → PROOF-MAP → LEMMAs, statuses start `open`/`cited`)
   - got a certificate → `workflows/verify-certificate.md` (hash first, check, script-generated CHECK-RUN, then statuses)
   - searching for examples → `workflows/hunt-counterexample.md` (floats screen, only exact arithmetic asserts; hits refute conjectures, empty searches support them)
   - citations → `workflows/audit-references.md`
   - stating a conjecture → `workflows/propose-conjecture.md` (origin from the plan's policy, exact instances first, formal statement compiled from a stub and confirmed by a human)
   - proving or refuting one → `workflows/attempt-proof.md` (one attempt per route, attested by `attest_lean.py`; the agent fills only assumptions, deviations, handoff)
2. Gate before every commit: `python3 scripts/graph_gate.py <your-artifacts-root>`.
3. CI (`.github/workflows/gates.yml`) re-runs both gates on push.

## 5. With Constructor Studio (optional)

The kit follows the SDLC-kit layout (`.cf-studio-kit.toml` canonical manifest, `constraints.toml` for `cfs validate`):

```bash
cfs kit install omniscale-ai/studio-kit-qi
cfs validate .
```

`cfs validate` adds the static layer: required sections per artifact kind, ID grammar (`cpt-{system}-{claim|cert|run|thm|pm|lem|vplan|rplan|conj|attempt|criterion}-{slug}`), and the reference chains (CLAIM ← CERTIFICATE ← CHECK-RUN; CONJECTURE ← PROOF-ATTEMPT; success criteria ← PROOF-ATTEMPT verdict rows). *Note: installation against a live Studio instance is not yet exercised — file an issue if the manifest schema drifts.*

## 6. The full Constructor Fabric flow (validated end-to-end 2026-08-11)

Scenario: you know only a paper (arXiv:2510.15143) and its repo (github.com/vgitton/fast-inflation), and want a gated verification project.

```bash
# 1. Studio + project
pipx install git+https://github.com/constructorfabric/studio.git
mkdir verify-ejm-gitton && cd verify-ejm-gitton && git init
cfs init --yes                                 # installs SDLC kit by default

# 2. This kit (local path or GitHub)
cfs kit install --path /path/to/studio-kit-qi --install-mode copy
cfs validate-kits --kit studio-kit-qi          # expect: all passed

# 3. Fetch the object of study
git clone https://github.com/vgitton/fast-inflation external/fast-inflation
shasum -a 256 external/fast-inflation/data/*certificate*   # record hashes

# 4. Author artifacts from kit templates (.cf-studio/config/kits/studio-kit-qi/artifacts/*/template.md)
#    docs/qi/CLAIM/... CERTIFICATE/... — follow workflows/verify-certificate.md
#    Conventions cfs validate enforces: ID line right under H1; a Table of Contents
#    section (generate with `cfs toc docs/qi/**/*.md`); ID system prefix must match
#    a registered system.

# 5. Run checks -> CHECK-RUN artifacts
python3 .cf-studio/config/kits/studio-kit-qi/scripts/checkers/fast_inflation.py \
    external/fast-inflation/data/srb_222_certificate.txt \
    --repo external/fast-inflation --target srb --system qi --cert-id cpt-qi-cert-srb-222 \
    --check-run docs/qi/CHECK-RUN/RUN-srb.md

# 6. Register artifacts: add a [[systems]] block (kit = "studio-kit-qi") to
#    .cf-studio/config/artifacts.toml listing each file with its kind.

# 7. Gates
cfs validate                                              # static: structure, IDs, chain
python3 .cf-studio/config/kits/studio-kit-qi/scripts/graph_gate.py docs/qi   # semantic
```

Result in the validated run: two certified claims (EJM 2×2×4 via the ported original checker — environment diversity; SRB 2×2×2 via the kit's independent checker — implementation diversity), both gates green.

Known rough edges at the time of that run, since fixed: the checker now takes `--system`/`--cert-id`/`--run-slug`; `graph_gate.py` still expects kind-named subdirectories (by design: one root per pack or per project); the manifest is `.cf-studio-kit.toml`.

## 7. Updating the kit in your project

The kit's source of record is **github.com/omniscale-ai/studio-kit-qi**. If you installed from GitHub (`cfs kit install omniscale-ai/studio-kit-qi`), updating is one command from your project root:

```bash
cfs kit update studio-kit-qi -y
cfs validate-kits --kit studio-kit-qi     # expect: all passed
cfs validate                              # new constraints may tighten rules for existing artifacts
```

Notes:

- Resources marked `user_modifiable` (constraints, workflows, templates) are **overwrite-protected**: if your installed copy differs from what the previous version shipped, the update declines those files and prints the exact `--approve-overwrite <resource-id>` flags to accept them. Run interactively (drop `-y`) to approve file-by-file, or pass the printed flags. This is deliberate — your local customizations are never silently clobbered.
- If you originally installed from a local checkout (`cfs kit install --path …`), the update command will say **"Kit 'studio-kit-qi' has no registered source — skipping"** — local copy-mode installs register no update source. Either keep updating with an explicit path (`cfs kit update studio-kit-qi --path /path/to/studio-kit-qi -y`), or switch the source once:

  ```bash
  cfs kit install omniscale-ai/studio-kit-qi --force   # re-registers GitHub as the source
  cfs kit update studio-kit-qi -y                      # works from now on
  ```
- With no releases tagged yet, updates track the default branch (`authority: github_default_branch`). Once versions are tagged, `cfs kit update` follows releases and `--version` pins one.
